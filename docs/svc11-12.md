# SVC 11: reading the directory count

`int sys_image_count(void)` returns how many entries the IMG1 directory contains. That number is the `count` field in the image header. `ls` uses it to decide how many names to request with SVC 12.

| Result | Condition |
|---:|---|
| `1..32` | The image is a valid IMG1. The value is the number of directory entries. |
| `-1` | The image fails the section 6.1 checks. |

The call takes no arguments. It reads the image in place at `0x00200000` and does not copy it, write to it, or print.

## Call path

1. `src/parser.c execute_command()`
2. `ls` calls `sys_image_count()`.
3. The stub in `lib/syscalls.s` executes `svc #11`.
4. `svc_dispatch` calls `sys_image_count_impl` in `kernel/syscall.c`.
5. `img1_count` in `kernel/loader.c` validates the image, then reads bytes 12..15.

## Stub

```asm
sys_image_count:
    svc #11
    bx lr
```

`svc #11` enters the kernel. The call has no arguments, so `r0`, `r1`, and `r2` are ignored.

`bx lr` returns to C. The kernel has written the count, or `-1`, into the saved `r0`.

## Handler: `sys_image_count_impl`

```c
static uint32_t sys_image_count_impl( uint32_t a0, uint32_t a1, uint32_t a2 )
```

The three arguments exist because every system call has the same shape. SVC 11 does not use them.

```c
(void) a0;
(void) a1;
(void) a2;
```

These casts mark the unused registers so the compiler does not warn about them.

```c
return (uint32_t) img1_count();
```

`img1_count` returns an `int`. A count of `1..32` stays the same value. `-1` becomes `0xFFFFFFFF`, which the caller reads back as an `int`.

The function is registered in the `svc_dispatch` table:

```c
[SYS_IMAGE_COUNT] = sys_image_count_impl,
```

`SYS_IMAGE_COUNT` is 11, so `svc #11` arrives here. An empty table entry would return `-1`.

## `img1_count`

```c
int img1_count( void )
```

Public loader function. It returns the directory count, or `-1` when the image is invalid.

```c
if ( !img1_validate( IMG1, IMG1_MAX_SIZE ) )
    return -1;
```

`IMG1` is the image at `0x00200000`. `IMG1_MAX_SIZE` is 2 MiB. `img1_validate` checks the magic, version, size, directory, names, and overlaps, and it reads the `count` field itself while doing so. If it returns 0, that field is not trusted and SVC 11 returns `-1`. The shell prints `error: no valid image`.

```c
return (int) read_u32( (const uint8_t *) IMG1 + 12 );
```

Bytes 12..15 are `count`, a little-endian `uint32_t`. `read_u32` rebuilds it one byte at a time. After validation the value is between 1 and 32, so the cast to `int` keeps it positive. The function reads those four bytes only after the whole image has been accepted.

## Who uses it

`ls` in `src/parser.c` stores the result in `count`. If `count < 0`, it prints `error: no valid image` and does not call SVC 12. Otherwise it loops from `0` to `count - 1` and asks SVC 12 for each name. Three directory entries make `ls` receive `3` and request the names at indexes 0, 1, and 2, in directory order.

# SVC 12: copying one directory entry name

`int sys_image_name(unsigned index, char *name, unsigned capacity)` copies the name of IMG1 directory entry `index` into the caller's buffer, including the final NUL.

| Result | Condition |
|---:|---|
| `0` | The complete name, including the NUL, was copied. |
| `-1` | The image is invalid, the index does not exist, `capacity` is outside `1..16`, the buffer is outside the caller's RAM partition, or the name does not fit. |

When the name does not fit, the first `capacity - 1` characters are still copied and terminated with a NUL. FLASH is not a valid destination. The image in FLASH is never modified.

## Call path

1. `src/parser.c execute_command()`
2. `ls` calls `sys_image_count` (SVC 11), then loops from 0 to count calling `sys_image_name(i, buffer, 16)`.
3. The stub in `lib/syscalls.s` executes `svc #12`.
4. `svc_dispatch` calls `sys_image_name_impl` in `kernel/syscall.c`.
5. The handler checks the capacity and the partition.
6. `img1_name` in `kernel/loader.c` reads the name from the image and writes it into the buffer.

The loader knows the IMG1 format. The system call knows the current task. That is why the pointer check does not live in `loader.c`.

## Stub

```asm
sys_image_name:
    svc #12
    bx lr
```

`svc #12` enters the kernel. The compiler has already placed `index` in `r0`, `name` in `r1`, and `capacity` in `r2`. The hardware saves these registers in the exception frame.

`bx lr` returns to C. The kernel has written the result into the saved `r0`, so the caller finds it in the return value.

## Handler: `sys_image_name_impl`

```c
static uint32_t sys_image_name_impl( uint32_t a0, uint32_t a1, uint32_t a2 )
```

`a0` is the index, `a1` is the buffer address, and `a2` is the capacity. They are the caller's three registers.

```c
if ( a2 < 1 || a2 > IMG1_NAME_SIZE )
    return (uint32_t) -1;
```

`IMG1_NAME_SIZE` is 16. A capacity of 0 has no room for the NUL. A capacity above 16 is not a name field. The call is rejected before any other check: with a length of 0, `in_range` would also accept a pointer that merely sits on the edge of the partition.

```c
const struct tcb *t = tcb_current;
```

`tcb_current` is the task that executed `svc`. For `ls`, that task is the shell.

```c
if ( t == 0 || !in_range( a1, a2, t->part_start, t->part_end ) )
    return (uint32_t) -1;
```

Without a task there is no partition, so the call is rejected. `in_range` requires every one of the `capacity` bytes to lie in `[part_start, part_end)`. The comparison is `len <= end - p`, so `p + len` cannot wrap. FLASH is outside every RAM partition, so a pointer into the image is rejected here and `img1_name` is not called.

```c
return (uint32_t) img1_name( a0, (char *) a1, a2 );
```

The buffer has been accepted. The loader copies the name and returns `0` or `-1`. The cast to `uint32_t` keeps `-1` as `0xFFFFFFFF`, which the caller reads back as an `int`.

The function is registered in the `svc_dispatch` table:

```c
[SYS_IMAGE_NAME] = sys_image_name_impl,
```

`SYS_IMAGE_NAME` is 12, so `svc #12` arrives here. An empty table entry would return `-1`.

## `img1_entry_at`

Finds the requested entry. It returns `NULL` when the image is invalid or the index does not exist. The first 16 bytes of the entry are the name.

```c
static const uint8_t *img1_entry_at( unsigned index )
```

It is `static`: only `img1_name` uses it.

```c
if ( !img1_validate( IMG1, IMG1_MAX_SIZE ) )
    return NULL;
```

`IMG1` is the image at `0x00200000`. `IMG1_MAX_SIZE` is 2 MiB. `img1_validate` checks the magic, version, size, directory, names, and overlaps. If it returns 0, SVC 12 does not read a name and does not write to the buffer.

```c
const uint8_t *bytes = (const uint8_t *) IMG1;
```

The image is read byte by byte. The format is little-endian, and the reader does not depend on alignment.

```c
uint32_t count = read_u32( bytes + 12 );
```

Bytes 12..15 are `count`, the number of entries. `read_u32` rebuilds the little-endian value. After validation the value is between 1 and 32.

```c
if ( index >= count )
    return NULL;
```

The index is rejected before the multiplication. An index that is too large cannot make `index * 24` overflow.

```c
uint32_t directory_offset = read_u32( bytes + 16 );
```

Bytes 16..19 say where the directory starts. Validation has already required that offset to be aligned and inside the image.

```c
return bytes + directory_offset + (uint32_t) index * IMG1_ENTRY_SIZE;
```

Each entry occupies 24 bytes. The pointer is the start of entry `index`. Because `index < count` and the directory lies inside the image, the address stays in FLASH.

## `img1_name`

```c
int img1_name( unsigned index, char *name, unsigned capacity )
```

Public loader function. It returns `0` when the whole name fits, and `-1` otherwise.

```c
if ( name == NULL || capacity < 1 || capacity > IMG1_NAME_SIZE )
    return -1;
```

This is the same limit as the system call, repeated here because this function writes. An illegal capacity or a null pointer produces no write. The handler checks this too, so under normal calls this branch does not run; it protects the function if another part of the kernel calls it.

```c
const uint8_t *entry = img1_entry_at( index );
if ( entry == NULL )
    return -1;
```

The image is invalid or the index is outside the directory. The function returns without writing.

```c
unsigned int length = 0;
while ( length < IMG1_NAME_SIZE && entry[length] != 0 )
    ++length;
```

It counts the characters before the first NUL, at most 16. The bytes after the NUL, inside the 16-byte field, are not part of the name.

```c
if ( length == 0 || length == IMG1_NAME_SIZE )
    return -1;
```

A valid name has 1 to 15 characters and a NUL inside the 16 bytes. A length of 0 means an empty field. A length of 16 means the NUL is missing. `img1_validate` has already rejected these cases; this check avoids inventing a name when the field is not terminated. Nothing is written.

```c
unsigned int stored = length + 1;
```

`stored` is the number of bytes to write, including the NUL. `length` is at most 15, so the sum is at most 16 and does not overflow.

```c
if ( stored > capacity )
    stored = capacity;
```

When the name does not fit, only `capacity` bytes are written. The last of them will be the NUL.

```c
for ( unsigned int i = 0; i + 1 < stored; ++i )
    name[i] = (char) entry[i];
```

It copies the characters, excluding the last byte reserved for the NUL. When `stored == 1` the loop does not run: the buffer receives only the terminator.

```c
name[stored - 1] = 0;
```

It terminates the string. `stored` is at least 1, so the index is valid. Bytes in the buffer past this position stay as the caller left them.

```c
if ( stored != length + 1 )
    return -1;
return 0;
```

If `stored` was shortened, the name did not fit: the prefix is in the buffer and the result is `-1`. If `stored` is still `length + 1`, the name is complete and the result is `0`.

Example with `zebra`, which occupies 6 bytes including the NUL:

| `capacity` | Buffer | Result |
|---:|---|---:|
| 6 | `zebra\0` | `0` |
| 5 | `zebr\0` | `-1` |
| 1 | `\0` | `-1` |
| 16, 15-character name | the 15 characters and the NUL | `0` |

## Who calls it

`ls` in `src/parser.c` first asks for the count with SVC 11. If the count is negative, it prints `error: no valid image`. Otherwise, for every index from `0` to `count - 1`, it calls `sys_image_name` with a 16-byte local buffer. A valid directory name always fits in 16 bytes, so the result is `0` and the shell prints the line. The buffer is on the shell stack, inside the partition `0x20000000..0x20000fff`, so the `in_range` check accepts it.
